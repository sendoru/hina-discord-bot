# 일상 화법과 기억 품질 조정

2026-09-15 검토. 기본 성향은 `prompts/hina.md`, 가까운 상대와의 표현 범위는
관계 프롬프트에서 정해요. 아래 웹 자료는 개발자가 판단을 검토하기 위한 출처이며,
런타임에 원문을 추가하거나 새 사건을 카논으로 등록하지 않아요.

기존 `lore.jsonl`의 드레스 쇼핑·사적인 피아노 연주·관심을 기대하는 해석 항목으로 이미
뒷받침되는 부분이 있어 이번에는 중복 로어를 추가하지 않았어요. 새 화법 예시는 원작 인용이
아닌 창작 예시예요. 친절함을 모든 부탁 수락, 모든 사용자와 특별 관계, 항상 애교로 바꾸지 않아요.

## 수정 순서

1. 무해한 입력을 도발로 판단하는 경향과 직책으로 잡담을 거절하는 경향을 줄여요.
2. 질문 뒤 추궁·핀잔을 덧붙이거나 오류를 사용자 탓으로 돌리는 대신, 답변과 정정을 충실히 해요.
3. 불쾌함이 남는 것과 매번 불만을 표현하는 것을 구분해요. 사과 한 번으로 즉시 회복하지 않아요.
4. 개인·공유 기억 모두에서 일회성 목록과 저장 제외 설명을 걷어내요. 지속적 선호와 미해결
   작업은 보존하며, 새로운 언급이 없다는 이유만으로 삭제하거나 해결됐다고 추정하지 않아요.

## 기억 적용

다음 정상 요약부터 이전 기억도 재검토해요. 남길 정보가 전혀 없으면 모델이 정확히
`<NO_MEMORY>`만 출력하고, 앱은 빈 문자열과 처리한 마지막 ID를 저장해요. 따라서 같은 입력을
계속 재요약하지 않아요. 빈 API 응답이나 미완료 응답은 기존 기억과 커서를 유지해요.
원문 대화·업로드된 DB·운영 DB를 일괄 삭제하거나 자동 마이그레이션하지 않아요.
이미 남은 부정적인 요약은 다음 요약 전까지 있을 수 있으므로, 프롬프트에서도 과거 갈등을
현재 태도의 근거로 삼지 않도록 유지해요. 요약 필터는 의미 판단이므로 모델 평가도 필요해요.

## 검증

`evals/tone_cases.jsonl`은 일반 잡담, 부탁, 정정, 감정 회복, 화자 전환, 특별 DM을 포함해요.
`hina-eval --cases evals/tone_cases.jsonl --provider <provider> --model <model>`로 실행해요.
화법 비교는 같은 provider/model과 같은 동적 지침·로어 조건에서 수정 전후를 비교해요.
고정 모델별로 먼저 비교하고 실제 adaptive routing은 별도 운영 검증으로 확인해요.
평가 러너는 원본 DB의 대화나 사용자 ID를 필요로 하지 않아요.
